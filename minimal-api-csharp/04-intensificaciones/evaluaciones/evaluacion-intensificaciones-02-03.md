# Evaluación del momento de intensificación y fortalecimiento 2 y 3 — Saberes previos

> Registro docente formal de la evaluación del momento de intensificación y fortalecimiento «Saberes previos» (Encuentros 2 y 3) · Curso: Minimal API con C# .NET 6. Define destinatarios, objetivos mínimos, criterio de resultado, equivalencia entre versiones y asignación. Se aplica en la plenaria de cierre del Encuentro 3.

## 1. Identificación

| Campo | Detalle |
| --- | --- |
| Instancia | Momento de intensificación y fortalecimiento «Saberes previos» — Encuentros 2 y 3 de 36 |
| Aplicación | Plenaria de cierre del Encuentro 3: 25 minutos de resolución dentro de los 40 minutos de la plenaria |
| Destinatarios | Todo el curso, según condición diagnóstica: grupo de recuperación y grupo de profundización resuelven la misma evaluación en la versión asignada |
| Modalidad | Ejercicio pequeño individual, en papel, sin computadora |
| Duración | 25 minutos |
| Puntaje | Sin puntaje numérico: resultado Apto / No apto aún por objetivo mínimo |
| Uso de celular | No permitido |
| Material consultable | Únicamente la hoja del ejercicio y lapicera |

## 2. Objetivos mínimos del momento

Corresponden a las expectativas de logro del tramo «Recuperación pedagógica y profundización de saberes previos» de la planificación anual:

| OM | Objetivo mínimo | Encuentro de origen | Se verifica en |
| --- | --- | --- | --- |
| OM1 | Operar la terminal para navegar carpetas, listar contenidos y crear carpetas | 2 | Parte 3 |
| OM2 | Describir el ciclo de petición y respuesta entre cliente y servidor a partir de una URL (protocolo, dominio, ruta) | 3 | Parte 1 |
| OM3 | Leer documentos JSON simples: pares clave-valor, tipos de valores, elementos de un arreglo | 3 | Parte 2 |
| OM4 | Expresar operaciones sencillas como secuencias ordenadas de pasos | 2 y 3 | Parte 3 |

## 3. Estructura del ejercicio

| Parte | Contenido | OM |
| --- | --- | --- |
| Parte 1 | URL y respuesta: identificar las partes de una URL (protocolo, dominio, ruta) y explicar quién pide y quién responde en el ciclo | OM2 |
| Parte 2 | Lectura de un JSON corto: cantidad de pares clave-valor, tipo de cada valor, cantidad y tipo de los elementos de un arreglo | OM3 |
| Parte 3 | Archivos y terminal planteados en papel: comandos para navegar, listar y crear carpetas, y la secuencia ordenada para entrar a una carpeta y ejecutar un programa | OM1 y OM4 |

- Sin tareas de programación: el ejercicio no pide escribir ni ejecutar código; la terminal se resuelve planteando los comandos en papel.
- Misma estructura en ambas versiones: mismos objetivos, mismos requisitos y misma forma de cada ítem; cambia el dominio y los datos.

## 4. Criterio de resultado: Apto / No apto aún por objetivo mínimo

- Cada objetivo mínimo (OM1 a OM4) se marca **Apto** o **No apto aún**, con los criterios de corrección del `evaluacion-intensificaciones-02-03-anexo-docente.md`.
- **Apto en el momento:** los cuatro objetivos mínimos alcanzados.
- **No apto aún:** al menos un objetivo mínimo sin alcanzar; se registra cuál o cuáles.
- El resultado es aún provisorio: orienta la continuidad (`05-continuidad/continuidad-01-saberes-previos.md`) y se revisa antes del primer cierre de unidad; no desaprueba ni inhabilita.
- Para el grupo de profundización, la misma grilla verifica que el piso común quede consolidado.

## 5. Regla de equivalencia entre las versiones A y B

- Misma estructura: mismas tres partes, mismos objetivos, mismos requisitos y misma consigna ítem por ítem.
- Distinto dominio: la versión A usa el catálogo de una biblioteca escolar (URL y JSON de libros); la versión B, la playlist de una aplicación de música (URL y JSON de canciones).
- Distintos datos, misma forma: la URL tiene exactamente las mismas partes, y el JSON la misma cantidad de pares clave-valor, los mismos tipos y arreglos de la misma naturaleza; los comandos de la Parte 3 difieren solo en los nombres de las carpetas.
- El propósito de la equivalencia es que la versión asignada no otorgue ventaja ni habilite la copia entre compañeros.

## 6. Mecánica de asignación de versiones

- La versión (A o B) se asigna por posición en el aula (filas alternadas), según lo defina el docente al iniciar la aplicación, y se comunica en el momento.
- La asignación se registra en la planilla de resultados (alumno → versión → resultado por objetivo mínimo).
- El ejercicio es individual: alumnos de un mismo grupo de trabajo pueden tener versiones distintas; eso no afecta la instancia ni el grupo.

## 7. Corrección, registro y devolución

- Corrección inmediata al cierre de la plenaria, con las soluciones y criterios del `evaluacion-intensificaciones-02-03-anexo-docente.md` (documento docente: no se entrega a los alumnos).
- Devolución oral breve por alumno en el mismo encuentro; el resultado queda registrado cualitativamente en la planilla del momento.
- Los objetivos mínimos en No apto aún definen la pista de la instancia de continuidad de saberes previos y se revisan antes del primer cierre de unidad.
